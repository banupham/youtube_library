# Phase 6 — Viewer Robot Model

## 1. Scope

Viewer Robot is an **offline synthetic entity** used to model audience interest distributions.
It never opens YouTube, never clicks videos and never creates views, likes, comments,
subscriptions or other real engagement.

The project keeps three populations separate:

```text
Observed project profiles   = read-only browser-profile evidence
Synthetic Viewer Robots     = offline simulation entities
External real audience      = real people outside project control
```

Phase 6 only creates the second population.

---

## 2. Goal

Create structured initial viewers that can be consumed by Phase 7 Feed Simulation.
A viewer must not be generated by independently randomizing all 18 categories.
It should have:

- one strong primary direction;
- 1–3 adjacent secondary interests;
- low/background interests;
- limited exploration interests;
- intent preferences;
- exploration/novelty/stability parameters;
- deterministic random lineage.

---

## 3. Seed modes

### 3.1 `pure_synthetic`

Source:

```text
18-category taxonomy
+
seed interest relationship graph
+
random seed
```

Process:

```text
choose primary category
↓
select adjacent categories from relationship graph
↓
add small exploration/background interests
↓
normalize category vector
↓
derive intent + novelty/exploration preferences
```

This mode is useful for creating neutral simulation populations that are not derived from a real browser profile.

### 3.2 `observed_profile_prior`

Source:

```text
longitudinal profile_library/profile_<id>.json
+
relationship graph
+
random seed
```

The observed profile is treated as a **prior**, not copied 1:1.
The generator applies controlled perturbation and may add a small amount of adjacent exploration.
This allows one observed profile to seed a synthetic cohort around the same content neighborhood.

Example concept:

```text
1 observed profile
↓
500 synthetic viewers with similar but non-identical interests
↓
Phase 7/8 offline experiments
```

No generated robot inherits browser cookies, account credentials or the ability to act on YouTube.

## 4. Viewer schema

Canonical schema:

```text
schemas/viewer_robot.v1.schema.json
```

Core shape:

```json
{
  "schema_version": "1.0.0",
  "viewer_id": "viewer-...",
  "seed_source": "pure_synthetic | observed_profile_prior",
  "random_seed": 123,
  "lineage": {},
  "interest_model": {
    "category_vector": {},
    "primary_interests": [],
    "secondary_interests": [],
    "low_interests": [],
    "exploration_interests": [],
    "topic_vector": {}
  },
  "preference_model": {
    "exploration_rate": 0.0,
    "novelty_tolerance": 0.0,
    "diversity_preference": 0.0,
    "stability_preference": 0.0,
    "intent_preferences": {}
  },
  "simulation_state": {
    "step": 0,
    "interaction_count": 0,
    "last_video_id": null,
    "state_version": 0
  }
}
```

`simulation_state` is initialized in Phase 6 but only changed by later offline simulation phases.

---

## 5. Relationship seed graph

File:

```text
taxonomy/interest_relations.v1.json
```

The graph contains project-level priors such as:

```text
Technology ↔ Education
Technology ↔ Business
Gaming ↔ Entertainment
Sports ↔ Health
Food ↔ Travel
Entertainment ↔ Music
```

These weights are not claims about YouTube's real transition probabilities.
They only stop the synthetic population from being unstructured random noise.
Later phases may learn/replace parts of this graph from offline simulation and observed transition evidence.

---

## 6. Reproducibility

Generator:

```text
scripts/viewer/generate_viewers.py
```

Viewer random seeds and IDs are derived from:

```text
master seed
+
seed mode
+
source profile token when applicable
+
viewer index
```

Same inputs + same master seed produce the same interest/preference model.
`created_at` timestamps may differ.

## 7. CLI

### Pure synthetic population

```bash
python scripts/viewer/generate_viewers.py \
  --mode pure_synthetic \
  --count 1000 \
  --seed 42
```

Optionally force a primary content family for a cohort:

```bash
python scripts/viewer/generate_viewers.py \
  --mode pure_synthetic \
  --count 500 \
  --seed 42 \
  --primary gaming
```

### Seed from one observed longitudinal profile

```bash
python scripts/viewer/generate_viewers.py \
  --mode observed_profile_prior \
  --profile data/profile_library/profile_<id>.json \
  --count 500 \
  --seed 42
```

Output:

```text
data/synthetic_viewers/<batch_id>/
  manifest.json
  viewers.jsonl
```

Generated cohorts are gitignored because observed-prior batches may inherit personalized research priors.

---

## 8. What Phase 6 does not do

Phase 6 does **not**:

- rank videos for a viewer;
- simulate a Home feed;
- simulate a watch decision;
- simulate completion/skip/like/comment;
- change interests after interactions;
- access YouTube.

Those responsibilities are intentionally separated:

```text
Phase 6  Viewer initialization
Phase 7  Offline feed simulation
Phase 8  Synthetic interaction simulation
Phase 9  Interest learning/state update
```

---

## 9. Definition of Done

Phase 6 MVP is complete when:

- viewer schema exists and remains stable enough for Phase 7;
- pure synthetic mode generates structured viewers;
- observed-profile-prior mode generates synthetic cohorts from longitudinal profiles;
- same seed is reproducible;
- every viewer has normalized category weights;
- primary/secondary/exploration structure is present;
- preference parameters stay inside valid bounds;
- generated data is local/offline;
- unit tests cover reproducibility and observed-prior behavior.

---

## 10. Next design target: Phase 7

Phase 7 should take:

```text
Viewer Robot
+
Video Content Vector
+
relationship/context features
```

and produce a purely offline ranked feed.

The feed model should initially be transparent and decomposable, for example:

```text
viewer-content similarity
+ intent fit
+ novelty/exploration
+ freshness/demand proxy
+ transition/adjacency fit
```

No part of Phase 7 should send requests or interactions to YouTube.
